# Operate legends-gohighlevel

1. Resolve the selected module source and user workspace. Never save private reports or CRM exports into a managed source checkout.
2. Run `legends-gohighlevel doctor` (offline runtime check) and `legends-gohighlevel agency-config` (checks `~/.config/legends-gohighlevel/agency.json` for `company_id`, `worker_ssh`, `worker_container`, and `worker_user_id`, plus `GHL_TOKEN_ID`). Never read or scan local desktop browser profile folders (`AppData\Local\Google\Chrome`, `Edge`, `Brave`, `IndexedDB`, `Cookies`, or `Login Data`).
3. **For agency-wide investigations, sub-account feature flags, user permission errors, `+hubpro` alias sync, dashboard RBAC errors, Custom SMTP locks, rebilling drift, or Agency Snapshots V2 / bulk sub-account cloning:**
   - Run `legends-gohighlevel live-audit` first. It extracts the live worker `token-id` from the worker container's IndexedDB (`/profile/Default/IndexedDB/https_app.gohighlevel.com_0.indexeddb.leveldb`) via SSH (never touch `/profile/Default/Cookies`) and audits all 5 governance layers across the entire agency:
     - **Layer 1 (40 location feature flags):** `legends-gohighlevel agency-locations` or `legends-gohighlevel agency-locations --location-id <locationId>`. To enable all 40 `location.permissions` boolean flags, preview `legends-gohighlevel location-unnerf --all-locations` and apply after approval with `--apply --confirm-plan <sha256>`.
     - **Layer 2 (User V1/V2 scopes, Only Assigned Data, and `+hubpro` aliases):** `legends-gohighlevel agency-users` and `legends-gohighlevel user-inspect --email <email>`. To un-nerf a user's 57 V1 permissions and 130 V2 scopes, preview `legends-gohighlevel user-unnerf --email <email>` and apply after approval with `--apply --confirm-user <userId> --confirm-plan <sha256>`. To sync `locationIds` between a primary email and a `+hubpro` alias, preview `legends-gohighlevel user-sync-locations --user-id <targetUserId> --from-user-id <sourceUserId>` and apply after approval with `--apply --confirm-user <targetUserId> --confirm-plan <sha256>`.
     - **Layer 3 (Reporting V2 Dashboard RBAC across all default and custom dashboards):** `legends-gohighlevel dashboard-permissions --all-locations`. Preview `legends-gohighlevel unlock-dashboards --all-locations` and apply after approval with `--apply --confirm-plan <sha256>`.
     - **Layer 4 (Custom SMTP `Add Service` lock):** `legends-gohighlevel smtp-status --all-locations` and `legends-gohighlevel email-domains --location-id <locationId>`. Preview `legends-gohighlevel smtp-unlock --all-locations` and apply after approval with `--apply --confirm-plan <sha256>`.
     - **Layer 5 (4-store + 14-product SaaS Billing v2 rebilling):** `legends-gohighlevel rebilling-status --all-locations`. Preview `legends-gohighlevel rebilling-sync --all-locations --markup 5` and apply after approval with `--apply --confirm-plan <sha256>`.
     - **1-Command 5-Layer Full Un-Nerf:** To remediate all 5 governance layers on one or more sub-accounts (and optional user email + `+hubpro` alias) in a single plan, preview `legends-gohighlevel location-full-unnerf --location-ids <id1,id2> --email <email>` and apply after approval with `--apply --confirm-plan <sha256>`.
     - **Agency Snapshots V2 & Bulk Sub-Account Cloning:** List agency snapshots with `legends-gohighlevel snapshots-list`, inspect 16-category asset inventories with `legends-gohighlevel snapshot-inspect --snapshot-id <snapshotId>`, create/refresh snapshots with `snapshot-create` / `snapshot-refresh`, and push a snapshot to 1 or N sub-accounts via `legends-gohighlevel snapshot-push --snapshot-id <snapshotId> --location-ids <id1,id2>` (which automatically bulk-switches all cloned workflows to `draft` and unlocks dashboard RBAC unless `--keep-workflow-status` or `--skip-unlock-dashboards` is passed).
     - **Internal Bulk Workflow Status & Clone Readiness Audit:** Inspect workflows on any location via `legends-gohighlevel agency-workflows --location-id <locationId>`, bulk-switch workflow status (`draft` / `published`) in 1 HTTP call via `legends-gohighlevel workflow-bulk-status --location-id <locationId> --status draft` (`PUT /workflow/:locationId/change-status`, bypassing the public Workflows v3 beta gate), and audit clone readiness + brand-term leaks via `legends-gohighlevel location-clone-audit --location-id <locationId> --brand-terms <terms>`.
     - **Private Integration Token inventory:** `legends-gohighlevel pit-list --location-id <locationId>` lists masked PIT suffixes and assigned scopes.
   - Read `wiki/internal-backend-and-dashboards.md` for full `backend.leadconnectorhq.com` endpoint schemas and DTO rules (`permissionAccess` vs `permission`, top-level `companyId` on `PUT /users/:id`, 4-store rebilling DTOs, Snapshots V2, and internal bulk workflow status).
4. **For sub-account CRM, Workflows v3, Agent Studio AI, and Custom Objects operations (`services.leadconnectorhq.com`):**
   - Run `legends-gohighlevel subaccount-config` to verify `GHL_PIT` + `GHL_LOCATION_ID` or named profiles in `~/.config/legends-gohighlevel/config.json` (use `--profile <name>` to select a named profile, or `legends-gohighlevel profiles-matrix` to compare all profiles), then run `legends-gohighlevel doctor --live`, `legends-gohighlevel subaccount-audit`, or `legends-gohighlevel subaccount-rebrand-audit --brand-terms <terms>`.
   - Route read-only discovery to `subaccount-audit`, `subaccount-rebrand-audit`, `profiles-matrix`, `location`, `pipelines`, `opportunities`, `calendars`, `calendar-slots`, `workflows`, `workflow-step-types`, `workflow-inspect`, `workflow-logs`, `email-templates`, `trigger-links`, `forms`, `surveys`, `funnels`, `tags`, `objects`, `object-records`, `associations`, `voice-ai-agents`, `voice-ai-calls`, `conversation-ai-agents`, `custom-values`, `custom-fields`, `contacts`, or `conversations`. Keep `contacts`, `conversations`, and `voice-ai-calls` in their default PII-lean mode unless the user explicitly needs `--full` contact details.
5. Read `wiki/crm-operations.md` before mutating sub-account CRM or workflow state. Preview `custom-value-upsert`, `custom-value-delete`, `tag-upsert`, `tag-delete`, `contact-upsert`, `contact-tag`, `contact-note`, `opportunity-update`, or `workflow-status` first (`writes_sent: 0`). Show the exact `location_id`, resource ID, `before` state, `proposed` payload, and `sha256`.
6. After owner authorization, apply the exact request using `--apply --confirm-location <locationId> --confirm-plan <sha256>`. Check the returned `verified` field and `readback` object.
7. **For offline governance calculations:** Run `rebilling-audit` (`1.05x` Stripe processing-fee shield and 4-store sync payloads), `scope-audit` (V1/V2 user scopes and worker inheritance), `smtp-audit` (two-level Custom SMTP `Add Service` unlock), or `dashboard-audit` (Default Dashboard RBAC payload generator) and read `wiki/agency-governance.md`.
8. Save a private receipt only when requested or part of an authorized workflow. Use `templates/change-receipt.md` or `templates/unnerf-audit-receipt.md` in the selected Empire project.

Read `wiki/internal-backend-and-dashboards.md` for the 5-layer governance architecture and internal backend endpoints, `wiki/authentication.md` for PIT vs. OAuth and V1/V2 user scopes, `wiki/email-and-deliverability.md` for Custom SMTP and subdomain MX isolation, and `wiki/troubleshooting.md` for instant incident diagnosis. Do not enable ambient HighLevel/LeadConnector MCP servers.

Do not install a standalone module skill. The central `cto-legends` skill loads this recipe on demand.
